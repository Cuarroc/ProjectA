2.Duplicate submission: same identity reconciles to one accepted run/result.
3.Connection loss after possible acceptance: unknown until actual receipt reconciliation;zero blind repeated start.
4.Project switch: request/history/rights remain bound to original target, no stale cross-project action.
5.Hold/cancel: no new steps after hold;cancel requested≠confirmed process stop;native stop≤10s retained;no rollback claim from view close.

7.Honest states: observed acceptance/start/block/delivery/check each with source/time;unknown/failed remain distinct;UI text not completion authority.
