**D1 — medium — `src-tauri/src/api/credential_acl.rs:227` (called from `restrict_directory_to_current_user` at `:319`)**
`nNumberOfLinks > 1` is the right hard-link signal for a file. On NTFS it is the wrong signal for a directory: the count is 1 plus the number of immediate subdirectories, and ordinary files do not move it. `restrict_directory_to_current_user` runs that check before `restrict_handle`. One subdirectory — a nested folder the app or the user created, or a folder planted while the directory still inherits a loose ACL — makes every later issuance fail closed, and the directory DACL is never narrowed. That is a sticky wedge of the same shape as the cross-elevation failure this round was fixing. Junctions are already covered by `FILE_ATTRIBUTE_REPARSE_POINT`; user-mode directory hard links are not a practical Windows attack. Apply the link-count check only to files.

**D2 — medium — `src-tauri/src/api/credential_acl.rs:314`**
The directory is opened with `WRITE_DAC | READ_CONTROL` only. `refuse_links` then calls `GetFileInformationByHandle`, whose contract is `FILE_READ_ATTRIBUTES`. **Verdict: approve with conditions.**

{TokenUser, TokenOwner, Administrators} does not let a foreign non-admin through. Without `SeRestorePrivilege`, another local user can assign only their own SID or a group they belong to that has `SE_GROUP_OWNER`. They cannot stamp this process's user SID or `BUILTIN\Administrators`. `TokenOwner` is that same user SID, or Administrators on an elevated token, so it does not add a third identity a non-admin can plant. An Administrators-owned file remains readable by elevated admins; that matches the trade-off in the comment. The oracle's copy of the set will not catch a widened accept-list; `a_world_sid_is_not_an_accepted_owner` is the pin, once it compiles.

`open_with_sharing_retry` retries only Win32 32, at most 25 sleeps of 40 ms, then fails closed. Lock violation, access denied, and user-mapped file are not retried, and the loop cannot run forever. The file order (open without truncate, refuse links, `verify_owned`, restrict, then `set_len` + write) holds the exclusive handle across the check and the write, so a link cannot be swapped in after the check.

Do not merge until D1 and D3 are fixed on the directory path, D2 is confirmed or the directory access mask includes `FILE_READ_ATTRIBUTES`, and D5's new tests actually build. D4 should be fixed in this change: a cloud reparse point becomes a permanent fail-closed once `FILE_FLAG_OPEN_REPARSE_POINT` is set.
